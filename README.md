## 구현 계획
### 쉘에 대한 공부

### 전체적인 프로젝트 개요.
결국은 쉘 프로그램을 만들어야 합니다.
저는 쉘 프로그램의 기본 동작을 다음과 같은 3단계로 파악했습니다. 
  1. 입력 -> 2. 파싱 및 탐색 -> 3. 실행

#### 입력
이 파트는 크게 3 부분으로 나누어집니다.
* REPL (Read-Eval-Print Loop)
    =>  사용자가 입력한 코드를 한 번에 한 줄씩 읽어(Read) 평가/실행하고(Eval) 결과를 출력한 뒤(Print) 다음 입력을 기다리는 과정(Loop)을 반복하는 대화형 프로그래밍 환경입니다.
* 내장 명령어 구현
    
  => 별도의 실행 파일을 두지 않고 쉘 프로그램 내부에 구현된 명령어입니다. 이것을 구현해야 하는 경우가 있습니다. 새로운 프로세스에서 처리하면 의미가 없어지는 경우, 쉘 프로그램의 상태를 변경해야 하는 경우, 효율적으로 처리할 수 있는 경우입니다. 그래서 아래의 명령어들을 내장 명령어로 구현할 생각입니다. 
  
    => 다양한 방법을 구현할 수 있을 것 같습니다. 간단하게는 REPL 안에 if 문을 덕지덕지 다는 방법입니다. 다양한 내장 명령어가 추가된다면 가독성이 안 좋아지고 디버깅이 어려울 것 같습니다. 그래서 명령어 테이블을 만들고 각 명령어에 해당하는 함수를 구현할 생각입니다. 이렇게 하면 확장성이 좋아질 것으로 사료됩니다.
  * quit()
  * cd()
  * pwd()
  * echo()
* sigaction을 이용한 인터럽트 제어

    => 특정 시그널이 발생했을 때, 예기치 않는 결과가 발생할 수 있습니다. 이를 막기 위해, 시그널 핸들러로 처리해야 합니다. 에러를 막는 설정을 우선적으로 한 뒤에 편의 기능들을 설정할 수 있을 것 같습니다. 구현할 목록은 다음과 같습니다.
  * Ctrl+C: 서브 프로세스는 종료되어도 괜찮지만 이 메인 프로세스 자체는 exit()을 통해서만 종료되도록 할 것입니다.
  * Ctrl+\: 위와 비슷한 이유입니다.

#### 파싱 및 탐색
=> 사용자의 명령어를 파싱하고, 실행 파일을 찾아야 합니다.
1. 명령어 파싱
2. 파일 찾기 feat. getenv() -> PATH
3. 권한 확인 feat. access()/stat() -> 실행 OR 에러 처리

#### 실행
=> 프로그램을 찾았으면 실행해야 합니다. 어떤 프로그램을 실행하든 비슷하게 동작해야 하는 것들이 sequential하게 존재합니다. 이를 하나의 함수로 묶을 예정입니다. 실행해야 하는 프로그램는 파라미터로 받아야 할 것 같습니다. 
1. fork()
2. exeve()
3. 실행 환경 세팅
4. 실행
5. wait(), signal()
